# 设置页：说明收进 `ⓘ`，值放标签旁

来源：WSight v0.4.3 的设置面板（做法见其会话里的《设置项提示收纳方案》），2026-09-15 移植到 AIQuad。
这份文档记的是**移植时定下来的规矩和踩到的坑**，改 `settings.html` / `styles.css` 的设置页段落之前先读一遍。

---

## 一、要解决的问题

设置窗口的典型毛病是"越写越长"：每个开关下面跟一句解释，一行变两行，两行变三行。
用户要滚三屏才找到那个开关 —— 而设置页**一辈子只被认真读一次**，就是找控件的那次。

所以：**行内只放「名字 + 当前值 + 控件」。任何需要一整句话才能说清的内容，收进标签旁边一个
13px 的 `ⓘ` 圆点里，悬浮才显示。**

## 二、四条不能破的规则

1. **一行一件事。** 行底下不留说明句。要解释就进 `ⓘ`。
2. **值和提示分工。** 值是"现在是多少"、弱色、等宽数字；提示是"这是什么 / 为什么这么设计"，进 `ⓘ`。
   **值塞进 tooltip 等于把它藏起来。**
3. **别每行都挂 `ⓘ`。** 只在"用户会问为什么 / 这是什么"的行加。一屏十几个小圆圈就是新的噪音，
   比原来那几句说明还吵。
4. **标签列是定宽的（138px），控件紧跟其后 —— 标签里只放名字和一个 `ⓘ`。**
   多塞一个值（哪怕就三个字）就会把这一列撑开，**后面所有行的控件起点跟着错位**。
   「面板宽度」那个像素换算值就是因为这条被挪到滑块右边的：标签里只留 `30%`，
   `约 696 px` 跟着滑块走（它本来就是控件状态的一部分）。

## 三、视觉规格

| 项 | 规格 | 实现在哪 |
| --- | --- | --- |
| `ⓘ` 形状 | 13×13px 正圆，1px 实边，`border-radius: 50%` | `.st-info` |
| `ⓘ` 内容 | 字母 `i`，9px / 字重 700 / `font-style: normal`（载体是 `<i>`，不去斜体就歪） | `.st-info` |
| `ⓘ` 静止 → 悬浮 | 边框与文字同时变强调色，`transition: color .12s, border-color .12s` | `.st-info:hover` |
| `ⓘ` 光标 | `cursor: help` —— 悬浮就是全部交互，没有东西可以点 | `.st-info` |
| `ⓘ` 位置 | 紧跟标签文字之后，间距 6px；`flex: 0 0 auto` 防止被压扁 | `.st-row-label` |
| 标签列 | `flex: 0 0 138px`，`white-space: nowrap` | `.st-row-label` |
| 控件列 | 紧跟标签列、**左对齐**（`justify-content: flex-start`），`flex-wrap: wrap` | `.st-row-ctl` |
| 行本身 | flex，`gap: 10px`，`padding: 6px 0` | `.st-row` |
| 行分隔 | 只用 `border-top`，**首行不留线**；两侧夹了状态行的那两行单独补 | 文件末尾那组选择器 |
| 当前值 | 标签右侧，11.5px、弱色、`font-variant-numeric: tabular-nums`（拖滑块时不抖） | `.st-row-value` |
| 标题栏 | 高 40px，`-webkit-app-region: drag`，右侧留出系统按钮的位置 | `.st-head` |

## 四、AIQuad 上的具体落法

- **卡片走两列网格**（`.st-grid`）。设置窗口宽 800px，一行行铺满的话控件会离它自己的标签好几百像素远。
  需要整宽的加 `.wide`：面板与呼出、AI 服务、数据与缓存、关于。
  同排两张卡 `align-items: stretch` **等高**，上下边都齐 —— 两张卡行高一致，「代理设置」多一条状态行，
  各按自己高度收边的话底边会错开那一条的高度。⚠️ 别改回 `start`（=各按自己高度收边）。
- ⚠️ **`.st-row` 有个隐蔽的折行陷阱**：`.st-row-ctl` 默认 `flex-basis: auto`，意味着"按内容的
  `max-content` 估宽"；里面 `<input>` 没写宽度时，浏览器按默认 `size` 算约 195px。标签列 138
  加它一旦超出行宽，`.st-row` 的 `flex-wrap` 会把**整条控件列**挤到标签下方独占一行 ——
  行高 39px → 65px。并排的两张半宽卡只要有一边中招，底边就差出几十像素（「代理设置」比
  「浏览器内核」高出 54px 就是这么来的）。
  → 凡是"必须一行放下"的行，给 `.st-row` 挂 **`.st-row-inline`**（把 `.st-row-ctl` 的
  `flex-basis` 归 0，外层永不折行；真装不下时在**控件列内部**折，位置可控），
  并给撑宽的那个控件写显式 `flex-basis`（如 `#proxy-host { flex: 1 1 110px }`）。
  下拉框的宽度由**最长选项**决定，选项文案别写长（「不使用代理（直连）」→「直连」）。
- ⚠️ **半宽的两张必须挨着**，否则落单的那张会在右边留一大片空白（网格不会把后面的整宽卡拉上来填）。
  所以卡片顺序是：面板与呼出(wide) → 代理设置 + 浏览器内核(两张半宽) → AI 服务(wide)
  → 数据与缓存(wide) → 关于(wide)。**加卡片或调顺序时先看这条。**
- **属于整组的说明**（例如"隐藏只是从选择器里摘掉，已经开着的格子不受影响"）放**卡片标题右侧**那行
  10.5px 小字（`.st-card-head > span`），与标题 `baseline` 对齐，不占正文的行。
- **控件的说明挂在控件上**：例如"代理策略"这一列的解释（单独代理只在关掉登录态共享后生效）
  直接写成 `<th title="…">`，连 `ⓘ` 都省了。
- **状态/结果行**（代理测试结果、清理结果）夹在行之间，用 `.st-statusline`；
  没内容时用 `:has(> span:empty)` 整条收掉，不留一条空带。
- **「X 个快捷键已生效」是唯一例外：它挂在卡片标题行的右端**（`#sc-status` 是
  `.st-card-head` 的最后一个子节点，`margin-left: auto` 推到行尾，`:empty` 时收掉）。
  理由：它管的是整张卡四处快捷键（呼出 + 1/2/4 格）加起来的结果，贴着任何一行都会
  被当成那一行的附属。冲突时这里会显示"`Ctrl+Alt+X` 已被其它程序占用（呼出快捷键）"，
  文案可以很长 —— 所以 `.st-card-head` 保留 `flex-wrap: wrap`，实在放不下时它整块落到第二行。
  ⚠️ 覆盖它的样式必须带 `.st-card-head >` 前缀：光写 `.sc-status` 是 `(0,1,0)`，
  压不过 `.st-card-head > span` 的 `(0,1,1)`，颜色会被淡成卡片说明那一路（同样的道理也适用于
  `.ok/.warn/.err` 三个状态色）。⚠️ **别给它加第二个类名**：`settings.js` 与
  `shortcut-capture.js` 都是整条覆盖 `className = 'sc-status …'`，多余的类每次刷新状态都会被冲掉。
- **AI 服务列表限高 300px**、表头 `position: sticky`。条目数没有上限，不封的话整页高度会随条目数漂。
- **窄窗口**（<720px）退回单列并收窄表格的定宽列 —— 窗口是可缩放的，`table-layout: fixed` 下
  网址列会被挤到 0。
- **标题栏是自绘的**（见第五节），页面顶部那条 `.st-head` 同时就是窗口的标题栏。

## 五、关键取舍（含已知短板）

- **提示用的是浏览器原生 `title`，不是自绘浮层。** 换来零 JS、零定位计算、不遮控件、不会被窗口边缘
  裁切；代价是**显示延迟由系统决定（约 0.5~1s）、样式跟不了深色主题**（深色应用里系统 tooltip 可能是
  浅色的）、**触屏点不出来**。设置页属于"低频查阅"，这个买卖划算。要即时显示就得换 CSS `::after`
  或 JS 定位浮层，成本立刻上来 —— 先按原生做，不够再升级。
- **无障碍是当前实现的短板，但已补了一半。** `<i title>` 不可聚焦，键盘用户和读屏软件拿不到提示，
  所以每个 `ⓘ` 都写了 `tabindex="0"`（HTML 里逐个写死的，改的时候别漏）。
  补得更彻底要改成 `<button type="button" aria-label="…">` 或 `aria-describedby` + 隐藏文本。
- **`<select>` 必须有不透明背景色。** Chromium 画下拉弹层用的是元素自己的 `background-color`；
  一旦那个颜色带 alpha，它会放弃并改用**系统**菜单色 —— 浅色 Windows 上就是白底，而选项文字是浅色的，
  于是下拉看起来是空的。
- ⚠️⚠️ **给输入框写样式时，选择器不能带 `[type="text"]`。** AI 服务表里的框是 `settings.js` 用
  `document.createElement('input')` 建的，**没有 `type` 属性**；而属性选择器只认 DOM 上真实存在的属性，
  于是 `.st input[type="text"]` 那整条规则**从来没有命中过它们** —— 这几个框一直用系统的白底 +
  `rgb(118,118,118)` 灰边，在深色页面里就是几个刺眼的白块。
  现在统一用 `.st .st-table td input`（刻意比全局那条多一个 `.st`），字体、底色、圆角全部显式写一遍。
  **深色 UI 里出现"白块"，先查这一条。**
- **吸顶表头别用 `border-bottom`。** `border-collapse: collapse` 下那条边框归表格画，滚起来会丢；
  用 `box-shadow: inset 0 -1px 0 var(--line)` 代替，底色还必须是不透明的，否则下面滚过去的行会透出来。
- **隐藏的条目不用删除线。** `text-decoration: line-through` 是画在**输入框里的文字**上的，名字和网址
  会糊成一片，比"隐藏"这件事本身还抢眼。改用整行 `opacity: .5`（悬停提到 .85）+
  名称格左侧 `inset 2px 0 0` 竖标。
- **`.st-row` 与 `.st-row-ctl` 都留了 `flex-wrap: wrap`。** 控件挤不下时整块掉到下一行，而不是被卡片
  （`overflow: hidden`）从右边裁掉一截 —— 被裁掉的那部分完全看不见，用户只会觉得"这个开关不见了"。
- **开关仍然是真的 `<input type="checkbox">`**，只是 `appearance: none` 自己画。
  换成一个假 div 就得改 JS，而 `collect() → save()` 那条链路是拿事故换来的（见下），能不动就不动。
- **单选项必须留在文档里。** 停靠位置改成了分段按钮，但 `input[name="position"]` 仍然在 DOM 里
  （藏起来、由 `:checked + span` 负责那层皮），因为回归脚本靠 `input[name="position"]:checked` 判"有选中项"。

### 标题栏：为什么摘掉系统的

Windows 的**非激活**标题栏会被系统换一套配色重绘。设置页是深色的，所以鼠标一离开窗口，顶上就白一条
—— 用户看到的现象是"标题栏时黑时白，全看窗口有没有焦点"。

修法是不要系统标题栏，让页面里那条 `.st-head` 自己当标题栏：

- `main/index.ts` 的 `openSettings()` 里 `titleBarStyle: 'hidden'` +
  `titleBarOverlay: { color, symbolColor, height }`（保留最小化 / 最大化 / 关闭三个**系统**按钮，
  底色是静态的，不随激活状态变）。
- ⚠️ 这几处必须配套，改一个要连另外几个一起改：
  `titleBarOverlay.color` ↔ `--panel-bg`（`#15181f`）；
  **`titleBarOverlay.height` 必须比 `.st-head` 的 `height` 小 2**（现 38 vs 40）——
  叠加层是一块画在页面**之上**的不透明矩形，同高时它的底边正好压住标题栏下沿那一行像素，
  那条 1px 分割线就会在右上角三个按钮下面**整段消失**（2026-09-15 实拍：标题栏底边在物理
  第 366 行，高度 40 的叠加层恰好盖到第 366 行 → 右侧 160px 全被吃掉）。矮 2px 后线整个落到
  叠加层之外，下面那 2px 由 `.st-head` 自己的底色补上（同色，看不出接缝），按钮只上移 1px；
  拖动窗口改由 `.st-head` 的 `-webkit-app-region: drag` 承担 —— 往这条里放按钮时，
  记得给按钮 `-webkit-app-region: none`，否则点它等于拖窗口。
- 右侧要给系统按钮让位：`padding-right: max(14px, calc(100% - env(titlebar-area-width, 100%) + 14px))`。
  `env(titlebar-area-width)` 是窗口控件叠加层给的实际可用宽度，取不到时退回固定 152px。
- **验证方式**：CDP 截图只看得到网页那部分（叠加层是原生绘制的，截图里根本没有它），
  系统按钮区、"失焦会不会变色"、"分割线有没有被盖住"都只有屏幕像素说了算。
  · 失焦变色：采样脚本 `.tmp/verify-titlebar.js` 截全屏 → 采标题栏上 5 个点 → 点一下桌面让它失焦
    → 再采一次。判据是两次**逐通道差为 0**。实测结果：底色 `#15181f`，失焦前后完全一致。
  · 分割线是否在按钮下面连续 → **`node scripts/verify-titlebar-line.js`**（正式回归脚本）：
    逐行统计"线色像素"在左段（`[窗口左+20, 窗口左+250)`）与右段
    （`[窗口右-140, 窗口右-5)`，正下方就是三个按钮）的命中数，两侧都要 ≥90%。
    负向对照 = 临时把 `.st-head` 压矮 2px 让线重新落进叠加层，此时右段必须报断。
    输出 `.tmp/headline-{after,before}-zoom.png` 两张放大对照图（连续 / 断开）。
  · 叠加层到底盖住了哪几行（根因诊断用）：把 `.st-head` 刷纯洋红、`.st-body` 刷纯蓝，
    全屏实拍后逐行找洋红/绿的横向范围 —— 洋红在右侧缺失的那一段就是叠加层。
    ⚠️ 这类采样 `.ps1` **必须纯 ASCII**：PowerShell 5.1 按 ANSI 读，中文注释会让它解析错乱
    （表现为 `$bmp` 为 null、每个像素都报 `GetPixel` 错）。脚本里用 `writeAscii()` 内联生成最稳。
  · ⚠️ 定位窗口别把两个函数混用：`findWindowsByPid(pid)` 返回该进程**所有**顶层窗口
    （含不可见的消息窗口，实测本应用有 6 个）；`listBrowserWindows()` 只返回
    `Chrome_WidgetWin_1` + 可见 + 带渲染子窗口的那些。要按标题/尺寸挑窗口用后者，
    只按 pid 筛会挑到消息窗口（那个的内衬与客户区原点完全不同）。
- 已知代价：没有系统标题栏就没有系统菜单，双击标题栏最大化也没了（都不是问题，但别以为坏了）。

## 六、回归契约（改 HTML 前先看这几条）

被脚本钉死的东西，**改名 = 静默坏掉**：

- `settings.js` 里 `$('id')` 引用的每个 id 都必须在 HTML 里存在。
  ⚠️ 缺一个会让 `collect()` 抛异常 —— 结果是**保存时任何一项都不生效，界面还一声不响**。
  真实事故：`opt-shared` 缺失导致"面板宽度比例"改了没反应。
- `.sc-input` 必须正好 4 个：`sc-toggle` / `sc-1` / `sc-2` / `sc-4`，且都是 `readonly`。
- `#ratio-presets button[data-ratio]`、`#ratio-val`（文本必须正好是 `40%` 这种）。
  ⚠️ `#ratio-val` 在**控件行**里（滑块右边），不在标签行 —— 别为了"对齐"把它挪回去，标签列会因此被撑开。
  单位只用百分比：早先它旁边还有一个换算出来的像素值（`约 673 px`），已按用户要求去掉
  —— 不同屏幕的像素值没法横向比较，而比例本来就是同一个数。
- `#ai-rows tr td.ops button`（第一个是隐藏开关）、隐藏行 `tr.className === 'ai-hidden'`、
  隐藏按钮的文案在 `隐藏` / `显示` 之间翻。
- `#save-result` 的文案（`已保存并应用` / `已自动保存`）。
- 缓存统计里 `#cache-stat` 必须含"可清理缓存"、`#cache-detail` 非空。

对应的脚本：`scripts/verify-settings.js`、`scripts/verify-settings-extra.js`、
`scripts/verify-shortcut-capture.js`。

## 七、怎么在不打扰用户的情况下跑这些脚本

官方那三个脚本自己 spawn Electron，**没法传 `--user-data-dir`**；而用户桌面上常常正开着装好的
AIQuad，它握着单实例锁，于是开发实例一启动就静默退出，脚本报的是"面板窗口没起来 / 设置窗口没起来"，
看着像功能坏了。

- Electron 的单实例锁按 **userData 路径**取，**不是**按 `%APPDATA%` 环境变量取 —— 改 `APPDATA` 没用，
  必须走 `--user-data-dir=<隔离目录>`（实测可行）。
- 隔离目录里放一份 config.json（可以从 `%APPDATA%\aiquad\config.json` 复制），
  把 `panes` 置空（否则会在用户桌面上弹出浏览器窗口）、`cacheCleanup` 设成 `off`
  （否则可能在启动时清掉真实档案目录里的缓存）。
- 起跑前把 `hidden` 标记和 `shortcuts` 清掉：真实配置里本来就可能藏着几条隐藏项、而用户的开机快捷键
  正被那个跑着的实例占着，留着会污染判据（"只隐藏了这一个"必然失败、"已保存并应用"会变成
  "已保存，但有快捷键没生效"）。
- 长连 CDP 在保存几次之后会偶发断开（报 `CDP not connected`，Windows 事件日志里没有崩溃记录，
  `verify-settings-extra.js` 的文件头也记着同一件事）—— 断了重连一次再发，别当成功能坏了。
- ⚠️ **采屏幕像素时必须减掉虚拟屏原点。** 全屏截图的原点是虚拟屏左上角（本机在 `(-1080, 0)`），
  而 `GetWindowRect` 给的是屏幕坐标 —— 不换算不会报错，只会**安静地采到别的窗口的像素**
  （第一次做标题栏验证时就栽在这，读出来一串白色，看着像"窗口被盖住了"）。
  另外 `GetWindowRect` 之前要先 `SetProcessDPIAware()`，否则拿到的是被 DPI 虚拟化过的坐标。
- 窗口标题被页面的 `<title>` 覆盖（是 `设置 · AIQuad`，不是 `openSettings()` 里那个 `title` 选项），
  用 `FindWindowW` 找窗口时按**页面标题**找。
